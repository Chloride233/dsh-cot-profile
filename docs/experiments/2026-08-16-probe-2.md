# 实验记录 · 2026-08-16 · 探针实验 2：装配 → 轨迹侧对照（n 扩大）

> 状态：进行中
> 工具：dsh-cot-profile v0.1（minBlocks=3）+ probe-verify.mjs

## 目的

在实验 1 基础上扩大样本（n≥3），验证 standard vs minimal 装配的轨迹侧判别
是否稳定可复现。

## ⚠️ 方法论修正（2026-08-16 事后核对）

实验 1 归档的结论基于 `session` 头部 `agentPreset` 字段，**该字段不可靠**——
它记录的是会话创建时的默认元数据，不是实际装配。正确口径（本实验采用）：

- **实际装配 = `agent-preset/selected` 事件（data.agentPreset）**，辅以
  **工具调用集**交叉验证（minimal 装配面 = bash + str_replace_editor 两工具；
  standard 装配面 = 全套工具）。

### 历史会话核对表（双证据）

| 会话 | 头部字段 | selected 事件 | 工具调用集 | 真实装配 | 判定 |
|---|---|---|---|---|---|
| 实验1 A（9a6a0114）| standard | 无事件 | bash,read,edit,write | **standard** | mixed |
| 实验1 B（84b14458）| standard | **minimal** | bash×7 | **minimal** | spec |
| 实验2 r1 A（f14ef96c）| standard | **standard** | bash,read,edit,write | **standard** | react |
| 实验2 r1 B（ff448d90）| standard | **minimal** | bash,str_replace_editor | **minimal** | mixed |

结论：实验 1 的"cordis vs minimal"与"四会话全 standard"两种说法**均不成立**；
真实对照是 standard vs minimal（对照组本身成立，方向大体符合预期：minimal 偏
spec 侧、standard 偏 react/mixed 侧），但 n=2 存在 mixed 波动。实验 1 归档文档
保持原样（数据即记录），本表为事后修正口径。

### 观察：任务形态主导 > 装配

两轮共 8 个探针会话（standard×4、minimal×4）**全部判 mixed（过渡带）**，
未出现实验 1 的 spec 侧判定。与社区观察一致：**长提示词 + 早期密集工具调用
会把轨迹推向过渡带**（router-standard 5.1 触发矩阵：工具 schema 面是锚定变量，
控制面工具/长描述会扰动轨迹；minimal persona + 21 工具目录曾出现 1/2 ambiguous）。

我们的双 bug 任务 = 长提示词 + 强制"先跑诊断脚本"（read/grep/bash 密集调用），
两个装配都被推入过渡带。**装配差异被任务形态掩盖**。下一轮需分离变量：
短提示词 + 少工具 vs 长提示词 + 多工具，同装配对照。

|---|---|---|---|---|

### n=3 完整矩阵与结论

| 组 | r1 | r2 | r3 | 归纳 |
|---|---|---|---|---|
| standard | mixed(3块不足) | react 0.62 | **react 0.85** | 2×react + 1 数据不足 |
| minimal | spec 0.65 | mixed(真实混合) | **spec 0.85** | 2×spec + 1 真实混合 |

**结论**：strong-signal 判定修复（runaway 指标 → 高置信落侧）后，装配对照在
n=3 下成立：standard → react 侧、minimal → spec 侧，4/6 正确落侧，2 个 mixed
均有合理解释（数据不足 / we+letMe 真实混合）。与 router-standard / modeltest
方向一致。任务形态（长提示词 + 密集工具）会混入第一人称口吻，但未淹没装配
指纹——修复前被算法误判为全 mixed。
