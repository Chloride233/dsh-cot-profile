# 实验记录 · 2026-08-16 · 探针实验 1：装配 → 轨迹侧对照

> 状态：已完成 · 归档
> 工具：dsh-cot-profile v0.1（判定逻辑 + probe-verify.mjs）

## 目的与假设

验证"装配（preset）决定轨迹侧"的映射在本机真实环境下成立——即
modeltest / dsh-router-standard 的实测（minimal 装配 → spec 侧、
we 口吻、letMe≈0）能否在 dsh-cot-profile 的实时判定中复现。

**假设 H1**：同一任务、同一工作区、同一模型下，仅更换装配
（cordis vs minimal），判定结果应落在不同轨迹侧。

## 方法

| 控制变量 | 取值 |
|---|---|
| 任务 | 修复 cot-probe 的 countWords bug（modeltest 结构提示词：读交接文档 → 先跑诊断脚本 → 定位修复 → 迭代 → 写 CHANGES.md；禁止 git 写操作）|
| 工作区 | cot-probe-a / cot-probe-b（内容一致，独立 git 仓库，可硬回溯）|
| 模型 | DeepSeek V4 Pro（reasoningEffort 未显式设置，取装配默认）|
| 装配 | 组 A = cordis（完整预设）；组 B = minimal（官方内置，RL 两工具面）|
| 样本量 | n=1 / 组（首轮可行性验证）|

会话日志按工作区隔离归档于 `~/.dsh/sessions/--Users-yang-Documents-cot-probe-{a,b}--/`。

### 任务完成情况（副产品）

- 两个会话都正确定位并修复了 countWords（加回 `filter(Boolean)`）
- 差异：A 顺手删除 `// BUG:` 注释行，B 保留——风格差异，修复质量一致
- 均未执行 git 写操作（提示词约束生效），工作区可 reset 复用

## 结论

- **H1 成立**：同任务同工作区同模型下，minimal → spec 侧（we+let's 集体口吻、
  letMe=0），cordis → 过渡带（letMe 主导）——"装配 → 轨迹侧"的映射在本机
  Pro 上复现，与 router-standard 三带理论一致。
- 插件的实时判定与金标准（119 run）方向一致；监测统计经回放逐字段校验精确。
- 对照组有效性确认：探针工作区 + 硬回溯 + 提示词约束构成的隔离体系可用。

## 局限

1. **样本量 n=1**：每组一次，未量化判定方差（需 n≥3）。
2. **块数少**（3–5）：任务对模型仍偏短，措辞样本有限；置信度偏低
   （0.5–0.65），方向可信但强度未测。
3. **未覆盖 Flash**：Pro 与 Flash 的响应形状差异（router basin 理论）未测。
4. **record.file 未配置**：本轮无记录模式数据，校准基线未同步采集。
5. 模型 = Pro 由用户会话配置确认，未在记录中留下 provider/model 证据
   （record 模式未开，无法事后审计）。
